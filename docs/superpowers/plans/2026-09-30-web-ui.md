## Shared Architecture

Keep the existing Django application and PostgreSQL database. Serve one Django template with small, dependency-free JavaScript and exactly one stylesheet from `/app/`; use same-origin DRF endpoints for lists, details, review, and imports. Keep the existing JSON health endpoint at `/`.

## Shared Constraints

- No login, authorization, user accounts, or role-specific behavior. Writes are limited to claim `status`/`notes` (Phase 2) and the two import POSTs (Phase 3). Unauthenticated write access requires restricting deployment network exposure.
- Normal CSRF protection on all same-origin write endpoints; DRF `SessionAuthentication` does not enforce CSRF for anonymous requests. CSRF is not authorization.
- Upper/lower panes occupy 40%/60% of viewport height with independent scroll. Exactly one stylesheet (`workspace.css`); no frameworks, inline styles, or JS-generated CSS. Server-derived content is rendered via `textContent`, never raw `innerHTML`.
- Do not ship `Trial.raw`, `Publication.raw`, or other large JSON fields in list responses. Prefer existing relations and source section constants; do not regenerate claims/judgements in request handlers.
- `fetch_trial_publications()` timeouts are ignored for now with a TODO in `django_app/lib/clinical_trials.py`; a browser timeout is never proof the server finished.
