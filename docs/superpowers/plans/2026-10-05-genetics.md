# Genetics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a first-class Genetic entity linked from gene NERs, trials, publications, claims, and claim trail snapshots, while exposing ClaimGroup claim types and keeping ClaimGroup Genetic relations empty for now.

**Architecture:** Add a `Genetic` Django model with the same entity fields as `Disease` and `Intervention`, then link matching NER rows in a dedicated pipeline stage before claim processing. Propagate Genetic relations to newly generated Claims and ClaimTrails, and provide a separate one-time function to backfill existing Claims from their linked NERs. ClaimGroups continue to group by exact disease/intervention sets, now also including `claim_type`; their Genetic relation remains empty and is not populated by linking, grouping, or backfill.

**Tech Stack:** Django 6.1, PostgreSQL, Django REST Framework, vanilla JavaScript workspace.

**Spec:** User requirements and clarifications in the 2026-10-05 conversation: Genetic is distinct from Biomarker; Biomarker must not be changed; ClaimTrails stores Genetic IDs in an array like its existing disease/intervention snapshots.

## Global Constraints

- `Genetic` has `name` and `mesh` fields matching `Disease` and `Intervention`, plus inherited `BaseModel` audit fields and metadata.
- Match NER labels `Gene_or_gene_product` and `Gene` without case sensitivity.
- Keep `Biomarker` behavior and schema untouched.
- Store claim-trail Genetic IDs in an integer array and preserve full immutable snapshots in `meta`.
- Re-fetching a Trial or Publication clears its Genetic source relation along with its other derived entity relations.
- A one-time, manually invoked `backfill_claim_genetics()` populates existing Claim Genetic relations from their linked NERs after NER-to-Genetic linking has run; it is not part of the recurring pipeline.
- Do not populate `ClaimGroup.genetics` in this implementation. Existing and newly created ClaimGroups retain an empty Genetic relation (`[]`).
- ClaimGroup grouping is based on exact disease and intervention ID sets plus `claim_type`; Genetics do not participate in group matching or membership changes.
- `ClaimGroup.claim_type` is populated for existing groups from their member Claims during migration; unpopulated groups use the empty-string default.
- Keep the implementation NER-driven; do not add a new gene extraction model or direct PubMed/ClinicalTrials.gov gene import in this change.

**Interfaces:**
- Produces `save_ner_genetic() -> None` and `backfill_claim_genetics() -> int` in `lib.genetics`; the backfill returns the number of Claims whose Genetic relation changed.
- `save_ner_genetic` scans NERs with `genetic__isnull=True`, accepts labels whose case-folded values equal `gene_or_gene_product` or `gene`, trims and truncates mention text to 255 characters, extracts a `MESH:` link using the disease/intervention convention, upserts by MeSH then normalized name using `lib.entities.upsert_entity`, sets `ner.genetic`, and adds the Genetic to the NER's Trial or Publication relation.
- `backfill_claim_genetics` is a one-time, manually invoked, idempotent operation. For each Claim, it sets `Claim.genetics` to the distinct Genetics linked from that Claim's NERs; it does not modify ClaimGroup relations, group membership, claim content, status, or notes. Run it after migration and after `save_ner_genetic` has linked existing NERs; never add it to the recurring pipeline.
- Pipeline order: `save_ner_trials`, `save_ner_publications`, `save_ner_interventions`, `save_ner_diseases`, `save_ner_genetic`, then `save_claims`.
