| Name | Link | What it is |
|---|---|---|
| **Hugging Face Transformers** | [Documentation](https://huggingface.co/docs/transformers/index) | The standard Python library for downloading, running, fine-tuning, and serving transformer models. Its `pipeline("token-classification")` helper is the common quick interface for fixed-label NER checkpoints.  [huggingface](https://huggingface.co/docs/transformers/en/main_classes/pipelines) |
| **Hugging Face token-classification pipeline** | [Pipeline docs](https://huggingface.co/docs/transformers/en/main_classes/pipelines) | High-level Transformers inference wrapper for NER/token-classification models. It tokenizes text, runs the model, and can merge BIO token labels into entity spans with `aggregation_strategy="simple"`.  [huggingface](https://huggingface.co/docs/transformers/en/main_classes/pipelines) |
| **spaCy** | [Website](https://spacy.io/) | General Python NLP framework used to construct pipelines for sentence segmentation, tokenization, NER, rules, and custom processing. scispaCy and medSpaCy build on it.  [spacy](https://spacy.io/universe/project/medspacy) |
| **scispaCy** | [Project/docs](https://allenai.github.io/scispacy/) · [GitHub](https://github.com/allenai/scispacy) | Python spaCy extension for biomedical, clinical, and scientific text. Includes pretrained pipelines, specialized biomedical NER models, an entity linker, biomedical tokenization, POS tagging, and parsing.  [allenai.github](https://allenai.github.io/scispacy/) |
| **scispaCy `en_core_sci_sm`** | [Model list](https://allenai.github.io/scispacy/) | Small general scientific/biomedical spaCy pipeline; good for lightweight local processing and span detection. |
| **scispaCy `en_core_sci_md`** | [Model list](https://allenai.github.io/scispacy/) | Medium biomedical spaCy pipeline with a larger vocabulary and word vectors; a useful general baseline.  [allenai.github](https://allenai.github.io/scispacy/) |
| **scispaCy `en_core_sci_lg`** | [Model list](https://allenai.github.io/scispacy/) | Larger biomedical spaCy model with a much larger vocabulary and vectors; useful when you want a stronger local spaCy baseline.  [github](https://github.com/allenai/scispacy) |
| **scispaCy `en_ner_bc5cdr_md`** | [Model list](https://allenai.github.io/scispacy/) | Fixed-label biomedical NER model for **chemicals/drugs** and **diseases**, trained around the BC5CDR task. Directly relevant for generating candidate drug–disease pairs. |
| **scispaCy `en_ner_jnlpba_md`** | [Model list](https://allenai.github.io/scispacy/) | Fixed-label biomedical NER model for genes, proteins, DNA, RNA, cell lines, and cell types. |
| **scispaCy `en_ner_craft_md`** | [Model list](https://allenai.github.io/scispacy/) | Biomedical NER model based on the CRAFT corpus, with molecular-biology-oriented entity categories. |
| **scispaCy `en_ner_bionlp13cg_md`** | [Model list](https://allenai.github.io/scispacy/) | Biomedical NER model focused on the BioNLP Cancer Genetics task and related entity types. |
| **scispaCy EntityLinker** | [GitHub/docs](https://github.com/allenai/scispacy) | spaCy component for linking recognized entity mentions to a biomedical knowledge base using approximate string matching and nearest-neighbor search. Useful after NER when you need normalized IDs, not only text spans.  [github](https://github.com/allenai/scispacy) |
| **medSpaCy** | [GitHub](https://github.com/medspacy/medspacy) · [spaCy Universe](https://spacy.io/universe/project/medspacy) | Clinical NLP toolkit built on spaCy. Especially useful for clinical sections, contextual assertion, negation, uncertainty, and family-history handling. It is a toolkit for custom clinical pipelines, not a universal pretrained clinical NER model.  [spacy](https://spacy.io/universe/project/medspacy) |
| **medSpaCy ConText / assertion tools** | [medSpaCy GitHub](https://github.com/medspacy/medspacy) | Components for interpreting modifiers around a mention: negated, uncertain, historical, hypothetical, family member, etc. Useful after entity/relation extraction—for example, distinguishing “received drug X” from “no prior treatment with drug X.”  [spacy](https://spacy.io/universe/project/medspacy) |
| **QuickUMLS** | [QuickUMLS GitHub](https://github.com/Georgetown-IR-Lab/QuickUMLS) | Fast approximate matching tool for mapping clinical/biomedical text to UMLS concepts. Often paired with medSpaCy for terminology-oriented clinical concept extraction.  [github](https://github.com/medspacy/medspacy/discussions/244) |
| **MedCAT** | [GitHub](https://github.com/CogStack/MedCAT) | Clinical concept annotation and linking toolkit. Its core strength is mapping mentions to controlled medical terminologies—especially UMLS and SNOMED CT—rather than only producing generic labels like `DRUG` or `DISEASE`. |
| **Stanza** | [Biomedical/clinical models](https://stanfordnlp.github.io/stanza/biomed.html) | Stanford NLP’s Python library with pretrained biomedical and clinical NER models, plus syntactic NLP tools. It provides another local baseline independent of the spaCy ecosystem.  [stanfordnlp.github](https://stanfordnlp.github.io/stanza/biomed.html) |
| **GLiNER** | [GitHub](https://github.com/urchade/GLiNER) · [Hugging Face models](https://huggingface.co/urchade) | Local open-/zero-shot NER framework where you provide entity labels at inference time. Good for quickly trying custom labels such as `trial arm`, `dose`, `eligibility criterion`, and `primary endpoint` without first training a conventional token classifier. |
| **`knowledgator/gliner-multitask-large-v0.5`** | [Hugging Face](https://huggingface.co/knowledgator/gliner-multitask-large-v0.5) | General GLiNER checkpoint previously used as an example for local dynamic-label extraction. It is not biomedical-specialized, so use it as a flexible baseline rather than your final biomedical extractor.  [docs.knowledgator](https://docs.knowledgator.com/docs/cookbooks/biomedical-entity-extraction/index.html) |
| **GLiNER-BioMed** | [Paper](https://arxiv.org/abs/2504.00676) | Biomedical adaptation of GLiNER for open biomedical NER. You supply desired biomedical entity types in natural language, making it attractive for evolving clinical-trial and literature-mining schemas.  [pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC13259603/) |
| **OpenBioNER** | [Paper](https://aclanthology.org/2025.findings-naacl.47/) | Open-domain biomedical NER model that can identify previously unseen biomedical entity types from their natural-language descriptions, avoiding retraining for each new label schema.  [aclanthology](https://aclanthology.org/2025.findings-naacl.47.pdf) |
| **OpenBioNER-v2** | [GitHub](https://github.com/disi-unibo-nlp/openbioner-v2) | Later OpenBioNER model suite for lightweight zero-shot biomedical/medical NER. Relevant alternative to GLiNER-BioMed for custom entity schemas.  [huggingface](https://huggingface.co/blog/alecocc/openbioner-v2) |
| **IBM ZShot** | [GitHub](https://github.com/IBM/zshot) | Python framework for zero-shot entity extraction and classification; discussed as the integration layer used with OpenBioNER-style models and spaCy workflows. |
| **OpenMed NER** | [Project/paper](https://huggingface.co/papers/2508.01630) | Open-source family of biomedical NER models, evaluated across biomedical benchmarks involving chemicals, diseases, genes, species, and related entity types. Treat as a benchmark candidate for your own corpus.  [huggingface](https://huggingface.co/papers/2508.01630) |
| **OpenMed ZeroShot NER** | [Hugging Face example](https://huggingface.co/OpenMed/OpenMed-ZeroShot-NER-Pathology-XLarge-770M) | Domain-adapted zero-shot medical/biomedical NER models intended for medical and clinical text mining. |
| **`d4data/biomedical-ner-all`** | [Hugging Face](https://huggingface.co/d4data/biomedical-ner-all) | Fixed-label biomedical NER checkpoint trained on the MacCrobat corpus with 107 entity types. Convenient for broad, immediate extraction through the Transformers token-classification pipeline.  [huggingface](https://huggingface.co/d4data/biomedical-ner-all) |
| **BioBERT** | [Paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC7703786/) · [GitHub](https://github.com/dmis-lab/biobert) | Biomedical BERT encoder pretrained on PubMed abstracts and PubMed Central full text. It is a foundational model for biomedical NER, relation extraction, question answering, and fine-tuning—not by itself a complete NER or RE application.  [pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC7703786/) |
| **PubMedBERT** | [Hugging Face](https://huggingface.co/microsoft/BiomedNLP-PubMedBERT-base-uncased-abstract-fulltext) | BERT-family biomedical encoder pretrained from scratch on PubMed content with a biomedical vocabulary. Strong practical base model for fine-tuning NER and relation classification on scientific articles and trial protocols.  [link.springer](https://link.springer.com/article/10.1186/s12911-022-01967-7) |
| **BioClinicalBERT / ClinicalBERT** | [Hugging Face](https://huggingface.co/emilyalsentzer/Bio_ClinicalBERT) | Clinical BERT encoder initialized from BioBERT and trained further on MIMIC-III clinical notes. Better aligned with EHR/clinical-note prose than pure research literature.  [huggingface](https://huggingface.co/emilyalsentzer/Bio_ClinicalBERT) |
| **BlueBERT** | [GitHub](https://github.com/ncbi-nlp/bluebert) | Biomedical/clinical BERT-family encoder pretrained on PubMed and MIMIC-style clinical notes. A reasonable baseline when your corpus mixes literature and clinical prose.  [link.springer](https://link.springer.com/article/10.1186/s12911-022-01967-7) |
| **SciBERT** | [Hugging Face](https://huggingface.co/allenai/scibert_scivocab_uncased) | Transformer pretrained on scientific text across domains. Useful scientific-language baseline, though less biomedical-specific than PubMedBERT or BioBERT.  [link.springer](https://link.springer.com/article/10.1186/s12911-022-01967-7) |
| **DeBERTa-v3 biomedical NER models** | [BioMed_NER example](https://huggingface.co/Helios9/BioMed_NER) | Biomedical NER checkpoints based on DeBERTa-v3 rather than BERT. Potential evaluation candidates, especially when you want to compare modern encoder architectures.  [huggingface](https://huggingface.co/Helios9/BioMed_NER) |
| **BioREx** | [GitHub](https://github.com/ncbi/BioREx) | Biomedical **relation extraction** research framework from NCBI. It supports relation prediction among biomedical concepts such as chemicals/drugs, diseases, genes, and variants, using datasets including BioRED. It is best viewed as a strong starting point and training/evaluation framework, not a universal plug-and-play “drug used for disease” evidence extractor.  [pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC10370213/) |
| **BioRED** | [Dataset](https://huggingface.co/datasets/bigbio/biored) · [Paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC9487702/) | Rich biomedical relation-extraction dataset with annotated entities and relations across chemicals, diseases, genes/proteins, variants, and related biomedical concepts. Useful as a training/evaluation/data-format reference, not itself an inference model.  [pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC9487702/) |
| **BERT-GT** | [GitHub](https://github.com/ncbi/bert_gt) | Graph-Transformer relation-extraction implementation supporting cross-sentence, n-ary biomedical relations. It is relevant when your evidence requires multiple entities or relationships spanning more than one sentence.  [github](https://github.com/ncbi/bert_gt) |
| **BioRel** | [Dataset](https://huggingface.co/datasets/DFKI-SLT/BioRel) | Large biomedical relation dataset with 125 relations, constructed using UMLS knowledge and distant supervision. Useful for broad relation pretraining or candidate generation, but outputs should not automatically be treated as article-specific asserted evidence.  [pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC10551783/) |
| **CT-PubMedBERT-RE / BIORE** | [BioRel paper/tool context](https://pmc.ncbi.nlm.nih.gov/articles/PMC10551783/) | Relation-extraction tooling/checkpoints associated with BioRel and PubMedBERT-style models. A closer option to downloadable RE baselines, though you still need entity detection, candidate pair construction, and validation logic.  [pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC10551783/) |
| **Biomedical RE entity-marker method** | [Paper](https://aclanthology.org/2023.bionlp-1.35.pdf) | An RE input design pattern, not one package: mark the two target entities in a sentence, such as `<e1> osimertinib </e1>` and `<e2> NSCLC </e2>`, then classify the relationship between that pair. Useful for adapting BERT-family encoders to pairwise RE.  [aclanthology](https://aclanthology.org/2023.bionlp-1.35.pdf) |
| **Pairwise candidate generation** | [Biomedical NER + relation detection paper](https://www.frontiersin.org/journals/cell-and-developmental-biology/articles/10.3389/fcell.2020.00673/full) | Pipeline technique rather than a downloadable model: use NER spans to generate typed candidate pairs—e.g., `DRUG × DISEASE`—then classify each pair as `USED_FOR`, `NO_RELATION`, etc. This is the conventional architecture for your goal.  [frontiersin](https://www.frontiersin.org/journals/cell-and-developmental-biology/articles/10.3389/fcell.2020.00673/full) |
| **Joint entity–relation extraction** | [Overview example](https://www.mdpi.com/2078-2489/15/7/407) | Modeling approach that predicts entities and relationships together rather than running NER and pairwise RE separately. More complex than a pipeline; useful later for dense or nested relationships.  [mdpi](https://www.mdpi.com/2078-2489/15/7/407) |
| **LLM structured extraction** | [Biomedical GPT relation-extraction study](https://pmc.ncbi.nlm.nih.gov/articles/PMC11141827/) | Prompt-driven extraction of entities, relations, attributes, and evidence quotes into constrained JSON. Useful for rapid schema iteration and complex trial/article language, but requires strict validation and human evaluation.  [pmc.ncbi.nlm.nih](https://pmc.ncbi.nlm.nih.gov/articles/PMC11141827/) |
| **LLM-IE** | [Paper PDF](https://digitalcommons.library.tmc.edu/cgi/viewcontent.cgi?article=1535&context=uthshis_docs) | Open-source Python package/framework for LLM-based biomedical generative information extraction of drugs, conditions, adverse drug events, attributes, and relations. Closely aligned with evidence-record extraction workflows.  [digitalcommons.library.tmc](https://digitalcommons.library.tmc.edu/cgi/viewcontent.cgi?article=1535&context=uthshis_docs) |
| **AllenAI drug-combo extraction** | [GitHub](https://github.com/allenai/drug-combo-extraction) | Research dataset/codebase for extracting drug combinations from biomedical literature. More specialized than your drug–disease use case, but relevant if you later need combination-therapy evidence.  [github](https://github.com/allenai/drug-combo-extraction) |
| **PubTator / PubTator3** | [PubTator3](https://www.ncbi.nlm.nih.gov/research/pubtator3/) | NCBI literature-mining system that provides annotations for biomedical entities and relationships across PubMed/PMC. Useful as a discovery, comparison, or weak-label source; do not assume its outputs precisely implement your `USED_FOR` evidence definition.  [github](https://github.com/ncbi/BioREx/issues/11) |
| **UMLS** | [National Library of Medicine](https://www.nlm.nih.gov/research/umls/index.html) | Large controlled terminology/metathesaurus used to normalize clinical and biomedical concept mentions to canonical identifiers. Commonly used with MedCAT and QuickUMLS. |
| **SNOMED CT** | [SNOMED International](https://www.snomed.org/) | Standardized clinical terminology for diseases, findings, procedures, and more. Useful for normalizing clinical concepts after extraction. |
| **RxNorm** | [NLM RxNorm](https://www.nlm.nih.gov/research/umls/rxnorm/) | Standardized terminology for clinical drugs. Appropriate normalization target for extracted medication/intervention mentions. |
| **MeSH** | [NLM MeSH](https://www.nlm.nih.gov/mesh/) | Controlled vocabulary for biomedical literature indexing. Useful for literature-level disease, drug, and topic normalization. |
| **MONDO** | [MONDO Disease Ontology](https://mondo.monarchinitiative.org/) | Open disease ontology that integrates disease concepts across multiple sources; useful for canonical disease identifiers in a research-oriented evidence graph. |
| **ChEBI** | [ChEBI](https://www.ebi.ac.uk/chebi/) | Curated ontology/database of chemical entities, often useful for drug-like chemicals and molecular compounds. |
| **HGNC** | [HGNC](https://www.genenames.org/) | Official human gene nomenclature resource; use it to normalize genes and gene symbols extracted from papers. |
| **PMC Open Access / JATS XML** | [PMC Open Access Subset](https://pmc.ncbi.nlm.nih.gov/tools/openftlist/) · [JATS](https://jats.nlm.nih.gov/) | Article-source infrastructure rather than an ML model. Prefer PMC JATS XML for evidence extraction because it preserves title, abstract, sections, paragraphs, tables, references, and offsets/provenance better than raw PDF text. |
| **HunFlair2** | [Flair documentation](https://flairnlp.github.io/flair/master/tutorial/tutorial-hunflair2/overview.html) · [Hugging Face](https://huggingface.co/hunflair/hunflair2-ner) | Pretrained biomedical entity tagger and linker, distributed through the Python **Flair** NLP framework. It detects five entity types: **genes/proteins, chemicals, diseases, species, and cell lines**. It supports both recognition and normalization/linking.  [academic.oup](https://academic.oup.com/bioinformatics/article/40/10/btae564/7762634) |
| **Flair** | [Docs](https://flairnlp.github.io/flair/) · [PyPI](https://pypi.org/project/flair/) | PyTorch-based Python NLP framework that provides the runtime/API for HunFlair2 and tools for tagging, embeddings, and model training. Install with `pip install flair`; current PyPI information says it requires Python 3.9+.  [pypi](https://pypi.org/project/flair/) |
| **`hunflair/hunflair2-ner`** | [Hugging Face](https://huggingface.co/hunflair/hunflair2-ner) | The NER-only HunFlair2 checkpoint. Good if you want spans and types first, then plan to normalize/link with a separate step or tool.  [huggingface](https://huggingface.co/hunflair/hunflair2-ner) |
| **HunFlair2 linker** | [Flair tutorial](https://flairnlp.github.io/flair/master/tutorial/tutorial-hunflair2/overview.html) | Companion linking capability for mapping extracted mentions to biomedical knowledge-base identifiers. That is useful for converting surface text such as a chemical or disease synonym into a stable concept ID.  [academic.oup](https://academic.oup.com/bioinformatics/article/40/10/btae564/7762634) |
